# Cluster 4 — Terminals & Editors: findings

## 1. Key verified facts (dates, names, sources)

- **Teleprinter era predates the transistor.** Teletype Corporation came into being in **1928** (renamed from Morkrum-Kleinschmidt), part of AT&T/Western Electric from **1930**; Baudot code invented by **Émile Baudot in the 1870s**. The Friden Flexowriter's design elements date to the **1920s**. — Wikipedia: Teletype Corporation, Baudot code, Friden Flexowriter
- **Teletype Model 33: introduced 1963**, ASCII, **110 baud / 10 characters per second**, **upper-case only** (no lower-case, no `{ | } ~`), ~$1,000, over half a million built by 1975, production ended 1981. `tty` = Teletype, hence `/dev/tty`. — Wikipedia: Teletype Model 33
- **First keyboard attached to a computer: MIT Whirlwind, 4 July 1956** (Doug Ross's Feb 1956 memo proposing a Flexowriter as input). Whirlwind itself operational 1951, vacuum-tube. — UK Computing History; Wikipedia: Whirlwind I
- **ed: written by Ken Thompson, August 1969, on a PDP-7** — one of Unix's first three elements *alongside the assembler and the shell*. It is still **POSIX-mandated** and ships on virtually every Unix. Wikipedia's infobox says **1973**, its body says 1969 — a real date conflict to flag. — Wikipedia: ed (text editor)
- **QED (1965-66)** by Butler Lampson and L. Peter Deutsch "addressed teleprinter usage"; CRT support was *deliberately not added* because the design considerations differ. **TECO**, 1962, Dan Murphy at MIT, originally "Tape Editor and Corrector". — Wikipedia: QED (text editor), TECO
- **First Unix shell: Thompson shell, 1971** (Unix V1). **Bourne shell: work began 1976, released 1979 with Version 7 Unix** (Stephen Bourne, Bell Labs), replacing Thompson's `sh`. csh: Bill Joy, 2BSD 1978. ksh: David Korn, announced USENIX **14 July 1983**. **Bash: Brian Fox, GNU, released 8 June 1989**; current 5.3, 3 July 2025. zsh: Paul Falstad, 1990. — Wikipedia leads; Wikipedia: Edlin
- **Unix pipes: McIlroy's 1964 memo** ("garden hose"); pipes present in Unix **by 15 January 1973** (Version 3 man pages). — Wikipedia: Pipeline (Unix); TUHS wiki
- **Why line editors were terse:** ed's terseness "was appropriate in early versions of Unix, when a console was a teletype, modems were slow, and memory was limited"; error output is a single `?`. Peter Salus called ed "the most user-hostile editor ever created". — Wikipedia: ed
- **The PC line-editor chain:** `ed` → **CP/M's ED** → **EDLIN**, written by **Tim Paterson in two weeks in 1980** for 86-DOS, the only editor in early IBM PC DOS/MS-DOS; superseded by the full-screen **MS-DOS Editor in MS-DOS 5.0 (1991)**. — Wikipedia: Edlin, MS-DOS Editor
- **vi/ex: Bill Joy added visual mode to ex in 1976**; ex 1.1 shipped in 1BSD (March 1978), renamed `vi` in 2BSD (May 1979). **Emacs: 1976, MIT AI Lab**, TECO macros, started by Guy Steele, completed/named by Stallman. The two are genuinely simultaneous. vi's name comes from ex's `visual` command — "visual interface" is a backronym. — Wikipedia: Vi, Emacs
- **Screen editors needed cursor-addressing terminals:** ADM-3A **1976** (Lear Siegler; arrows printed on **HJKL**, which vi inherited), VT100 **1978**; Wikipedia notes such terminals "could support use of a full-screen text editor program without generating large amounts of paper printouts". Escape sequences standardised as **ANSI X3.64 / ECMA-48 / ISO 6429**. — Wikipedia: Teletype Model 33, ADM-3A, Terminal emulator
- **The graphical track is parallel, not later:** Xerox Alto first machines **1 March 1973**; **Bravo** (Lampson, Simonyi) first WYSIWYG editor, operational **14 September 1974**; **Maestro I** (Softlab, Munich) mid-1970s, originally "Programme-Entwicklungs-Terminal-System" (PET), ~22,000 installations, Boeing 1979 — the "first IDE" claim is Softlab/Wikipedia framing, not settled. — Wikipedia: Xerox Alto, Bravo, Maestro I, Softlab
- **Turbo Pascal: November 1983, $49.95**, Anders Hejlsberg, Borland — editor + compiler + debugger in one box, ~1/10th the price of rivals. **MacWrite: 1984**, shipped with the first Macintosh. — Wikipedia: Turbo Pascal, MacWrite
- **Windows shells:** MS-DOS/PC DOS from **12 August 1981** (86-DOS bought by Microsoft **27 July 1981**, $50,000, API-compatible with CP/M). **cmd.exe** arrived with **Windows NT 3.1, 27 July 1993**, "designed to be as compatible as possible with MS-DOS batch scripts". — Wikipedia: Seattle Computer Products, Windows NT 3.1; Microsoft Command-Line devblog
- **PowerShell:** **Monad Manifesto written August 2002** by Jeffrey Snover (published later on his blog, 1 Oct 2011); **PowerShell 1.0 completed November 2006** (announced at IT Forum Barcelona; used by Exchange 2007); **PowerShell Core 6.0, January 2018** — first cross-platform; **PowerShell 7.0, March 2020**, MIT-licensed; 7.5.x current, 7.4 supported to 10 Nov 2026. — Microsoft Learn; Microsoft devblogs; Wikipedia
- **Git Bash / Git for Windows:** effort **started August 2007**, originally MSys ("a stripped down version of Cygwin"), now MSYS2 — ships "a minimal POSIX emulation layer with Bash and Perl". **WSL 1 released 2 August 2016** (Linux syscalls implemented in the Windows kernel); **WSL 2 announced May 2019** — a real Linux kernel in a managed Hyper-V VM; most of WSL open-sourced 19 May 2025. — gitforwindows.org; Wikipedia: WSL
- **Windows Terminal:** source published **3 May 2019**, announced at Build **6 May 2019**, **v1.0 19 May 2020**; **default terminal since Windows 11 22H2 + Terminal 1.15, announced 18 October 2022**. Being a *window*, not a shell, is now explicit. ConPTY (Windows pseudo console) shipped **Windows 10 1809, announced 2018** — VS Code had been blocked without it. xterm: written **summer 1984** by Mark Vandevoorde. — Wikipedia: Windows Terminal, Xterm; Microsoft devblogs
- **AI surfaces arrived at different times:** GitHub Copilot announced **29 June 2021** (a VS Code/IDE extension); Cursor launched **March 2023** as a VS Code fork (Anysphere, founded 2022 by four MIT students); **Google Antigravity announced 18 November 2025** — described as *one platform containing a chat environment, an IDE, a CLI and an SDK*. — Wikipedia: GitHub Copilot, Cursor (company), Google Antigravity
- **First-hand check on the author's own machine** (Windows 11, build 10.0.26200): Windows PowerShell **5.1** present, **no `pwsh` (7.x)**; `cmd`, `wt`, `code`, `git` present; `wsl.exe` present but reports **"The Windows Subsystem for Linux is not installed"**; Git Bash has `ls`, `vim`, `nano`, `perl` but **no `apt`, no `pacman`, and no `ed`**. That last pair is a ready-made demonstration of "the command existing ≠ the tool existing" and of emulation vs a real Linux.

## 2. How strong teaching sources sequence and explain this

- **Crash Course Computer Science sequences exactly our way, and dates it:** #22 "Keyboards & Command Line Interfaces" (2 Aug 2017) → #23 "Screens & 2D Graphics" (9 Aug 2017) → **#26** "Graphical User Interfaces" (30 Aug 2017, framed as "a radical evolution from the command line interfaces found on all other personal computers of the era"). GUI is #26, not #24 — a correction verified directly. ~11 minutes, animation-led, almost no dates.
- **Charles Petzold's *Code* deliberately starts before the computer:** Chapter 1 "Best Friends" is Morse/Vail, then codes and combinations, then braille — the machine arrives last, built out of familiar objects. Reasoning: give the reader a physical object they can picture, then let the abstraction emerge. That authorises a Stage 0 that opens the terminal thread on teleprinters and telegraphy.
- **CS50 teaches the terminal inside a GUI, just-in-time:** cs50.dev is a browser VS Code on a cloud container; students meet `code hello.c`, `make hello`, `./hello` at the moment a task needs them, never as a standalone tour. Strength: no environment failure, motivation always present. Weakness for us: a beginner can use a shell for a year and still not know what a shell *is* — the gap our chapter targets.
- **Nand2Tetris builds the stack rather than narrating it** (12 projects: hardware → assembler → VM → compiler → OS). The transferable idea without the labour: teach each layer by the problem the layer below made unbearable — "every tool exists because doing it by hand stopped being tolerable."
- **What none of them do (our opening):** none teaches the terminal as a *hardware fossil*. CS50 uses commands without explaining why they look odd; Crash Course gives the CLI one episode and never mentions line editors; Petzold stops before tooling; general surveys teach today's tools with a framing paragraph. "The command line's oddities are constraints from the 1960s that never got removed" is a falsifiable, specific frame no beginner source currently owns.
- **Register evidence:** the sources that hold beginners are the ones that keep dates *out* of the reader's path and attach them to people and objects instead — matching the project's own light-citation rule for Stage 0.

## 3. Story / analogy hooks (with the break point)

- **The terminal is an ATM at the end of a wire** — you type, it prints, your money (the machine) is somewhere else. *Breaks at:* today's terminal usually has nothing at the far end — it's pretending.
- **A line editor is dictation, not editing.** On paper you cannot point at a word, so you name a line number and issue a correction; ed answers `?` when it doesn't understand. *Breaks at:* dictation has a human taking notes who tells you when you're unclear — ed does not.
- **Why nobody made it visual yet — do the arithmetic.** A 24×80 screenful is 1,920 characters; at the Model 33's 10 characters per second one repaint takes over three minutes. That converts "ed was primitive" into "ed was correct for the printer attached to it." (Arithmetic from cited specs, not a quote.)
- **A menu vs a counter.** A GUI shows every option — best when you don't know what you want. A CLI names the one thing you want — best when you do, and dangerous for the same reason. *Breaks at:* the CLI also lets you name the wrong thing confidently; that's the safety-floor material.
- **Phrasebook vs moving country** (Git Bash vs WSL): Git Bash speaks enough Unix to get by on Windows (MSYS2 emulation — observed: `ls` and `vim` are there, `apt` is not); WSL runs an actual Linux kernel with everything a citizen gets. *Breaks at:* a phrasebook is enough until you need a real institution — which is exactly what `apt install` is.
- **PowerShell pipes objects, Bash pipes text** — a box of labelled parts versus a sentence. *Breaks at:* parts from one maker don't always fit another's.

## 4. Structural recommendation

- **Verdict on the inherited decision: keep terminals before editors, but restate *why*.** It holds as *substrate before tool*, not as invention order — QED (1965) precedes the Unix shell (1971), and ed and the shell are near-twins (both 1969-71). Correct sentence: "screen editing is impossible before cursor-addressing terminals exist; the first editors are *defined* by the teleprinter constraint." Flag this so the chapter never claims a clean sequence it can't support.
- **Two chapters is well supported — both sides are thick.** Terminals: teleprinters, terminal/emulator, PTY/ConPTY, shell ×6, pipes/composition, remote shells, plus six named Windows-era tools. Editors: line editors, screen editors, modal editing, WYSIWYG, IDE, plugin ecosystems, web-tech editors, AI-integrated editors. Neither side is thin enough to merge; merge only if page budget forces it, and then as two parallel Lessons, not one narrative.
- **Flag the real false sequence in the *candidate* editor ladder.** "line editors → screen editors → GUI editors → IDEs" is not chronology: Bravo (Sept 1974) predates vi's first BSD release (1978); Maestro I sits between them; GUI editors only reach the public with MacWrite (1984); Emacs (1976) and vi (1976) are simultaneous. Recommend two interleaved tracks — text-mode and graphical — with the concurrency stated structurally, not smoothed.
- **Suggested terminal-chapter seams (4 Lessons):** ① the machine at the end of the wire (teleprinters → first keyboard 1956 → emulator); ② the shell and the pipe (1971 → 1989 → today); ③ six names, six different things (CMD / PowerShell / Bash / Git Bash / WSL / Windows Terminal — the tool table the owner asked to be complete); ④ the terminal today (SSH 1995 → OpenSSH 1999, headless servers, agents driving shells).
- **Suggested editors-chapter seams (4 Lessons):** ① editing without a screen (QED → TECO → ed → CP/M ED → EDLIN → MS-DOS Editor); ② when the screen arrived (ADM-3A/VT100 → ex/vi + Emacs, one era, two answers); ③ the parallel graphical track (Alto → Bravo → Maestro I → Turbo Pascal → MacWrite → IDEs → VS Code 2015); ④ the editor as a reading instrument, ending on AI-in-the-editor.
- **Concurrency and boundary flags to hand the orchestrator:** (a) teletypes start *before* Stage 0's own timeline — needs an explicit "this thread starts earlier than everything else here" signpost; (b) CP/M 1975 / MS-DOS 1981 belong to the PC-era chapter's *machine* story — this chapter should own the *interface* and cross-reference, or Unix and the PC get told twice; (c) the Unix chapter should own "Unix's first three programs: assembler, editor, shell" and hand both the shell and ed here; (d) the Whirlwind keyboard fact is the hardware cluster's to own — reference it, don't narrate it; (e) the SDE chapter must own "IDE as a reading instrument" if it wants it, so it isn't invented twice.
- **Answer on convergence (Q5): the AI surge is the shared *destination*, but the two threads did not arrive together.** AI entered the editor first (Copilot, 2021; Cursor, 2023) and the terminal second (2025 CLI agents), and both surfaces now coexist by design (Antigravity, Nov 2025: IDE + CLI + SDK under one brand). Recommend structuring the surge chapter as **two Lessons — AI in the editor, AI in the terminal** — because the verification surfaces differ: a diff in a file you can read versus a command and its output you must judge. That difference is the SDE-relevant point, and one merged narrative would lose it.
