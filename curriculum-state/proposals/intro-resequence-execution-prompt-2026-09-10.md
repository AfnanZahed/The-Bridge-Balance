## Background: why this restructuring is happening

The intro sequence currently opens with Spec-Driven Engineering (SDE) in
chapter 1 (`intro.md`), then spends chapters 2–4 on binary/language,
architecture, and (again) the two extremes and SDE. The project owner
flagged this as backwards: SDE is the *destination* of a beginner's journey,
not its opening move. The whole sequence is being reorganized around one
organizing principle, in the owner's own words: **an evolutionary thought
process — "0/1 -> .... -> SDE."** Every chapter is a rung on a ladder that
starts at raw binary and ends at the book's own engineering discipline,
built because the rung before it ran out of room — nothing is taught before
its natural place in that timeline.

Concretely this produced a 5-chapter structure (full detail and reasoning in
the proposal file from step 5 above):

1. **`intro-1-binary-to-programming.md`** — replaces
   `intro-2-binary-to-language.md`. Same transistor → bit → byte → ASCII →
   machine code → x86/ARM → punched cards → assembly → assembler → register
   chain, with one new beat, **"What Is Programming,"** inserted
   immediately after "register" and immediately before "high-level
   language" — the actual historical pivot from talking to the machine in
   its own terms to talking in a language built for humans. This is NOT a
   concept-first preface before the binary content (an earlier draft of
   this plan tried that ordering and the owner explicitly corrected it) —
   it is a rung positioned at its real evolutionary place. Then continues:
   high-level language → compiler → interpreter → abstraction.
2. **`intro-2-architecture-map.md`** — replaces
   `intro-3-architecture-map.md`. Content and scope unchanged — the "let's
   build one thing together" full-stack tour (platform, frontend, backend,
   API/HTTP/REST, database, auth, Git/GitHub, deployment, the same-map
   cross-platform callback, cybersecurity as a cross-cutting lens).
3. **`intro-3-editors-and-ides.md`** — new. From text editors to IDEs (how
   dev environments evolved) → What Is an IDE? (VS Code — owner will supply
   a real screenshot or short official clip) → AI-integrated IDEs (Cursor,
   Windsurf, Zed, Trae & more — same treatment as VS Code) → AI-assisted vs.
   AI-driven development, key differences.
4. **`intro-4-terminals-and-cli-agents.md`** — new. What is a terminal? →
   terminal types (CMD, PowerShell, Bash, Git Bash) → why terminal skills
   are non-negotiable → CLI-based coding agents, the next level (Claude
   Code, Codex, Gemini CLI — same treatment as VS Code) → how CLI agents
   use the terminal to code → Claude Code/Codex/other CLI agents, which is
   most famous → who should use Cursor vs. Claude Code.
5. **`intro-5-spec-driven-engineering.md`** — new finale. Full merge of
   `intro.md` (all of it — evidence studies, worked examples, the
   Specify/Design/Implement/Verify loop, Development-vs-Engineering) and
   `intro-4-two-extremes-and-sde.md` (vibe coding, over-caution, the two
   extremes, the safety floor), checked against the official docs from step
   6 above. This is the destination: everything the reader has now met —
   programming, architecture, IDEs, terminals, agents — gets named as
   exactly what SDE governs.

Three risks were flagged and resolved by the owner (full text in the
proposal file):
- **If `intro-5` turns out disproportionately long** once drafted: do not
  ship it as one flat file. Restructure it as its own sidebar **category**
  with nested sub-lesson docs — the same pattern Stage 1–4 already use (a
  folder holding an index doc plus numbered sub-lessons, wired into
  `sidebars.ts` as a collapsible category, not a single leaf item).
- **Chapters 3 and 4 name specific competing tools** (Cursor, Windsurf,
  Zed, Trae, Claude Code, Codex, Gemini CLI) that will date quickly. Both
  chapters need an explicit `<Callout type="info" title="Current as of
  writing">` (or `type="important"` if it should read more urgently) near
  where the named tools are introduced, stating the actual date you write
  the chapter and telling the reader to check the current landscape.
- **`intro-1`'s scope growing** was judged a non-issue — the concept of a
  programming *language* already existed implicitly in the old
  `intro-2-binary-to-language.md` (it already ends at "high-level
  language"); "What Is Programming" just makes that explicit for a
  beginner reader.

One more thing to reconcile while merging chapter 5: `intro.md`'s own
`teaches` list (see `prerequisite-graph.yaml`) names both "the
specify-delegate-inspect-verify framework" and "the specify-design-
implement-verify responsibility loop" — check whether these are the same
four-part framework under two different names or genuinely distinct, and
make the finale consistent. Similarly, `intro.md` says "the two failure
poles (surrender and resistance)" while `intro-4` says "the two extremes
(over-caution and over-trust)" — these read like the same pair under
different names (surrender ≈ over-trust, resistance ≈ over-caution) and
should land on one consistent naming in the merged chapter.
