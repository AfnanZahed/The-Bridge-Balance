# Proposals

Non-binding planning output from `curriculum-architect`'s Mode 1 (stage-level
structuring help). Files here look like `stage-0N-<slug>-<YYYY-MM-DD>.md` and
each one is a sketch — candidate lessons, a rough order, flagged risks — never
a decision. Nothing in this directory is read back automatically by any skill;
a human reviews a proposal and, if they agree with some or all of it, acts on
it themselves (typically by asking `curriculum-architect` in Mode 2 to turn one
accepted candidate into a real lesson brief, which is what actually adds a
`planned` row to `curriculum-state/ledgers/prerequisite-graph.yaml`).

This directory starts empty. A file appearing here means someone asked
`curriculum-architect` for stage-level planning help at some point — it is not
a sign that the book's structure is more decided than it was before.

---

## Promoting a decision out of this folder — added 2026-09-20

**A decision recorded only here does not bind anything.** That is by design, and
it has cost this project real work twice:

- The owner's light-register rule for Stage 0 (*"don't make it difficult or very
  complex or full of references, dates or citations, teach it very easily with
  examples, analogies, storybuilding"*) lived only in
  `whole-book-redesign-record-2026-09-14.md` for four days, inside a file whose
  own first line says nothing in it is a commitment. It lost to five binding
  rules pulling the other way, and a chapter shipped that the owner rejected.
- The same file's *"Stage 0 keeps its beginner-only audience exception"*,
  confirmed three times, never reached `canon/audience.md`.

**So: when the owner agrees to something in a proposal, promote it the same
day.** A decision that binds goes into `curriculum-state/canon/` — usually
`corrections.md` — and into the reading list of whichever skill has to obey it.
Then leave a pointer here saying where it went.

**Anything still only in this folder is a suggestion, whatever it says about
itself.**
