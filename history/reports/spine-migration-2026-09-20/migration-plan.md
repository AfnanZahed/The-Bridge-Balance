## 3. The rule that decides every row

**Principle.** A rule lives where the person who needs it opens it at the moment it applies, and there is one copy. A rule a writer applies while drafting a sentence or laying out a page belongs to the skill. A decision about what the book is, the safety floor, and the process rules belong to the canon. ADR-0007 decision 3 allows either direction and forbids keeping both copies.

| Canon file | What it is | Who keeps the text | Rows in both places | Why |
|---|---|---|---|---|
| `thesis.md` | The thesis, the stage table, the invariants, the safety wording | Canon | 17 | Cited by the constitution and read by planning and review, not only by the writer |
| `integrity-floor.md` | The CS50 academic-honesty and security floor | Canon | 9 | Absolute, so one copy |
| `research-and-comparison.md` | The two-pass research policy | Canon | 19 | Constitution VIII. It also governs platform work, so it cannot live inside a chapter-writing skill |
| `naming.md` | The three naming rules | Canon | 21 | It names every stage, chapter, section and label; the gate script and the architect protocol cite it |
| `audience.md` | Who the readers are, reading conditions, glossing, formatting | Split: canon for who the readers are (11 rows); the skill for glossing and formatting mechanics (18 rows) | 29 | `audience.md` itself sends the reader to `mixed-audience.md` §4 for the glossing mechanics |
| `voice.md` | Register, warmth, openings, examples | The skill for craft (39 rows); canon for process and topic decisions (11 rows) | 50 | `audience.md` says `language-register.md` *"governs every sentence and is the authority"* (C1-30) |
| `corrections.md` | The dated log of owner corrections | **Decision 2, answered: a rulebook.** The log keeps the live wording and the skill points into it | 53 | The owner chose this on 21 September |

Process rules (who reads what, what to record, when to stop and ask) stay in canon in every case. Where the skill restates one, the skill's copy becomes a pointer.

**The tombstone.** When a canon rule's text is removed, its heading, its section number and any quoted owner's words stay. Its body becomes one line: `→ Live rule: <file> <section>. Moved 2026-09-DD under ADR-0007.` Every existing citation still resolves, and none of the many files that cite the canon needs to change.

**The pointer.** In the skill, a pointer is never a bare link. It names the rule so the writer knows what is behind it: *"Names: every stage, chapter and heading name follows `naming.md` rules 1 to 3. Open it before naming anything."*

**The reading table.** `SKILL.md` gains one short section so the pointers carry weight. It says what to open in full, and when:

| When you are | Open, in full |
|---|---|
| Starting any chapter for this book | `corrections.md` (already required) and `audience.md` |
| Naming a stage, chapter, section or heading | `naming.md` |
| Writing about AI, about Engineering, or opening a stage | `thesis.md` |
| Drafting a Stage 2 chapter, or any security content | `integrity-floor.md` |
| Researching, or studying a source | `research-and-comparison.md` |
| Assembling the file | `chapter-production/reference/gate.md` |

**The superset rule.** A copy is converted only after the surviving text contains every operative detail the removed text had. Where it does not, the detail is merged first, by hand, and the row is marked `+merge` in Appendix A.

## 9. How each batch runs

**Roles.** Claude writes each batch's worksheet (the rows, the exact old text, the exact new text or the rule for it), decides every merge, reads every changed passage, and signs off. DeepSeek applies the edits from the worksheet: at most 20 rows per call, no exploring, one file set, `--effort high`, launches staggered 15 seconds apart, a 25-minute cap, one retry, one log line per row.

**Steps.**

1. **Back up** the batch's files to a folder outside the repo, with checksums.
2. **Worksheet.** For a tombstone or pointer the new text is templated. For a merge, Claude writes the merged sentence first.
3. **Apply** with DeepSeek.
4. **Audit the trace.** Only in-scope reads; writes only to the batch's files; every shell command read in full. `finalText` is not evidence.
5. **Verify** (below).
6. **Log** one line in ADR-0007's migration log.

**Verification, every batch.**

| # | Check | How |
|---|---|---|
| V1 | The surviving text contains every operative detail of the removed text | Claude reads each changed passage against its worksheet row |
| V2 | The rule now appears once outside records | Grep for a distinctive phrase |
| V3 | No canon heading, section number or filename changed | Diff of the heading lists before and after |
| V4 | Every pointer resolves | Script: the target file exists and the named section is there |
| V5 | The old phrase is gone everywhere it was stated | Repo-wide grep (`corrections.md` §17: fixing one layer is not a fix) |
| V6 | Line endings unchanged | Byte check; the repo is CRLF |

**After each phase:** `npm run build` (the five gates) and `node scripts/check-chapter.mjs` (run from `edu-site`), which must give the same result as before the phase.

**Stop conditions.** Any failed check restores the batch from its backup. A stalled call is split smaller; effort is never raised.

## 10. Risks

1. **Losing a detail when a copy becomes a pointer.** Guards: the superset rule, the 18 merge-first rows, and Claude reading every changed passage. The detail check is a heuristic (about half of what it flags is real), so each batch re-reads its rows.
2. **A dangling citation.** 13 to 40 live files cite each canon file. Guards: tombstones keep every heading, V3 and V4.
3. **A second session editing the same files.** Another session wrote a prompt record for the homepage on 21 September. Guards: a batch touches only its listed files, each edit is checked and then saved in one step so that a failed edit leaves the file unchanged, and each batch checks the files' modification times first.
4. **The plan rests on model labels.** The 24 flags and the 23 strongest detail flags were checked by hand and every quote by script. The other duplicated rows were checked only by the detail check.
5. **A stale external copy re-introduces the old rules** (decision 7).

Each batch is reversible from its backup, no phase deletes a canon heading, and phase 3 can stop after any batch.
