## Prompt

fix this too, while keeping in mind that the content writing will being done by the new lesson spine skill

## Response snapshot

The loose thread from PHR 0043 was `generate-chapter-manifest.mjs`: referenced by
the `gen:manifest` script but untracked, so a fresh clone would break on it.
Reading it before touching anything: it is a pure platform script, walking
`docs/**/*.{md,mdx}` for the `chapter_state` frontmatter key and emitting
`src/data/chapterManifest.ts`, which a swizzled sidebar component reads to show
a readiness dot per chapter. It does not decide, validate, or interpret chapter
state — it only mirrors whatever `chapter_production`'s gate already wrote.
That is the right shape: this fix stays entirely on the platform side, and
nothing about it touches or duplicates what `lesson-spine-authoring` or
`chapter-production` own.

**The real bug wasn't "untracked," it was a broken promise in the script's own
docstring.** It says: *"the generated file is committed so `docusaurus start`
works without a pre-step; `npm run build` regenerates it."* `package.json`'s
`build` script never called it — `check:frontmatter && check:refs &&
check:chapter && generate-search-index.mjs && docusaurus build`, no manifest
step anywhere. So the committed file (once committed) would only ever be
regenerated by someone remembering to run `gen:manifest` by hand; every other
build would silently ship whatever chapter states happened to be lying around,
which is the same "config naming something that used to be true" shape PHR
0042 hunted down — just aimed at a generated file instead of a doc.

Regenerated it once first, to check for drift before trusting it: identical
output to the untracked copy already on disk, so nothing had gone stale yet.
Wired `node scripts/generate-chapter-manifest.mjs` into `build`, immediately
before `generate-search-index.mjs` — same category of step, generated data
before `docusaurus build` compiles anything that might read it.

**Not touched, and not committed:** the sidebar component that actually
imports `chapterManifest.ts` (`src/theme/DocSidebarItem/Link/index.tsx`) is
itself untracked, part of the separate, in-progress sidebar-redesign work
already identified in PHR 0043 as not mine. At HEAD, before this commit,
nothing tracked imports the manifest at all — this fix makes the generator
correct and current for whenever that consumer lands, without adopting the
consumer itself.
