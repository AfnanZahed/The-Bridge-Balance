  • The levels: Stage → Course → Chapter → Lesson → Part (only when needed). A stage can hold more than one subject.

  • Stage 0 teaches theory and the first practical basics: the terminal, an editor, and the first programming. It is named “Introduction to SDE”, and that name belongs to Stage 0 only.
  • A Course is a difficulty band, not a subject. Every subject at that band is matched for difficulty, so several subjects share one chapter. Question A below has your example.
  • One page opens the book, before Stage 0. A 30-minute read on the problem, the solution, and “development” versus “engineering”. Its exact name is still being checked. Question C below has the detail.
  • Learning-first names. Stage and course names say what is learned, never the reader’s level.
  • Level labels are allowed. Beginner, Intermediate and Advanced go on the chapters and sub-chapters of a subject. A correction from me: I told you the rules still banned audience labels. That was wrong. The ban was removed on 20 September. I read it from an old copy of the rules.

Decided today, 22 September: agentic AI is taught inside SE

You settled the direction today. It changes the stage count and the shape of everything that follows.

  • Agentic AI is taught inside SE, never as its own stage. An agentic application is added where a concept genuinely pairs with it, in the same chapter where that concept is learned.
  • Three stages. Stage 0, Introduction to SDE. Stage 1, SDE Mastery (AI-Driven): basic to intermediate software engineering with basic to intermediate agentic applications. Stage 2, SDE Mastery (AI-Native): advanced software engineering with advanced agentic applications.
  • Credentials is a parallel track, not a stage. CS50P, CS50W and future certifications sit beside the stages. It is switched off for now, and its design is postponed.
  • Navigation happens at Course level — a difficulty band inside each stage. SE comes first, at full depth, and the agentic twin follows only where it genuinely pairs.
  • Students write code by hand first, then with a coding agent. Real agents run on free providers (Groq, OpenRouter). The scope is building with models, not building models: no ML, DL or NLP for now.
  • Substrate, Surface and Practice pairings are now a main philosophy of the book. Every Substrate and Surface pairing names its delta — what is genuinely new in the agentic version. There are no separate SDK-specific Parts.
  • The zero-knowledge floor now names Stages 0–1.
  • The 27-row topic sketch is a very rough idea, not a plan. Deployment and cloud are in it, but each topic is placed in Stage 1 or 2 when it is authored, and the topics and sub-topics are designed then.

Question A: how does a Course work when one chapter teaches several things? — you answered, 22 September

A Course is a difficulty band inside a stage, not one subject. Every subject taught at that band is matched for how hard it is, so they can sit in the same chapters. Your own example: a Beginner Course pairs basic Python, basic terminal use and a basic editor, and the first AI ideas — what a prompt is, what context and tokens mean, what an LLM and an agent are — with a few starting Claude Code commands such as /compact and /clear. Once that band is done, the next Course moves every subject up together: advanced Python or JavaScript and their frameworks, advanced Git and GitHub, deployment, full AI-tool use, and the harder Claude Code and OpenCode commands, with advanced prompt, context and loop engineering.

Not fixed yet: the exact topics above are your own examples, not the final list. Which subjects go in which Course, for each stage, is chosen when that part of the book is written.
