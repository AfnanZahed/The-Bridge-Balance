# Implementation Plan: book-foundation

**Branch**: `001-book-foundation` | **Date**: 2026-08-17 | **Spec**: [./spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-book-foundation/spec.md`

## Summary

Deliver the **first deployable textbook slice** of The Bridge Balance:

- Docusaurus 3.x site (already scaffolded in `edu-site/`) with TypeScript config, MDX-enabled chapters, and a four-stage sidebar.
- Six Stage 1 chapters authored under the **co-authoring workflow** defined in Constitution v2.0.0 Principle III (research → text → images → video).
- Three explicit chapter states (`placeholder` / `text-ready` / `video-published`) surfaced via a `<ChapterState />` badge.
- Vercel deployment via auto-detected framework (no custom `vercel.json`).
- GitHub Actions CI: `npm run build` exits 0; broken-link gate enforced; no required human reviewer.

Stages 2–4 stay as title-page stubs (Q4). Backend / RAG / auth / payments are explicitly out of scope.

---

## Technical Context

**Language/Version:** TypeScript 5.5.x (Docusaurus config + sidebars); Node.js ≥ 18 (per spec assumption).
**Primary Dependencies:** Docusaurus 3.7.x, MDX 3.x, React 18.x, Infima (Docusaurus CSS), prism-react-renderer (syntax highlighting).
**Storage:** None in Phase A — content is files-on-disk under `edu-site/docs/` (MDX) and `edu-site/static/img/` (images). Postgres/Qdrant are Phase B.
**Testing:** Smoke only — `npm run build` exits 0 + manual click-through. Vitest / Playwright deferred to Phase B.
**Target Platform:** Vercel free tier (auto-detected Docusaurus framework).
**Project Type:** Web — static site only. No backend in Phase A.
**Performance Goals:** < 3 s load on simulated 3G (SC-004); Lighthouse a11y ≥ 90 (SC-005); build exits 0 (SC-001).
**Constraints:** Free-tier only (Vercel + GitHub); no LLM spend; no DB / no auth; static-site scale (infinite via CDN).
**Scale/Scope:** Phase A = Stage 1 fully written (6 chapters) + Stages 2–4 stubs (per Q4). ~25 chapters at full content in steady state; 4 stages.

## Implementation Phases

The implementation phases break down as follows (full task list lives in `tasks.md`, generated by `/sp.tasks`):

### Phase 1 — Setup (verify scaffold)
- Confirm Docusaurus 3.7.x is installed and `npm start` boots.
- Confirm `docusaurus.config.ts` has `onBrokenLinks: "throw"`.
- Confirm `sidebars.ts` reflects the four stages.

### Phase 2 — Foundational (blocking prerequisites)
- Add `.github/workflows/ci.yml` for the CI gate.
- Add `edu-site/scripts/check-frontmatter.mjs` for frontmatter validation.
- Add `src/components/ChapterState/index.tsx` for the state badge.
- Wire `ChapterState` into a Docusaurus MDX component so every chapter auto-renders it.
- Add `vercel.json` only if framework detection fails (likely not needed).

### Phase 3 — User Story: Build & Deploy (Priority P1)
- Run `npm run build`; confirm exit 0.
- Push to a test branch; confirm Vercel deploy preview works.
- Configure Vercel project for the repo (one-time).
- Enable branch protection on `main` per R-009.

### Phase 4 — User Story: Co-authoring Workflow (Priority P1)
- Author one Stage 1 chapter end-to-end as proof:
  - Claude Code writes `01-foundations.mdx` (placeholder → text-ready).
  - Project owner produces one image, integrates it.
  - Project owner records a video (optional for Phase A proof).
- Confirm the `<ChapterState />` badge updates correctly through transitions.
- Confirm CI runs `npm run build` and rejects broken frontmatter.

### Phase 5 — Polish
- Update `edu-site/README.md` with the deploy workflow (mirrors `quickstart.md`).
- Add a "How to contribute" section referencing Constitution Principle III.
- Confirm Lighthouse a11y ≥ 90 on the deployed site (SC-005).
- Confirm 3G load < 3 s (SC-004).
