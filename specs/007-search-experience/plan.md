# Implementation Plan: Search Experience — Apple Spotlight (Home) + Expandable Bar (Chapters)

**Feature Directory**: `007-search-experience`
**Spec**: `specs/007-search-experience/spec.md`
**Status**: Active
**Created**: 2026-09-11

## Summary

Port the owner's two supplied reference components into the live Docusaurus site as the book's search:

- **Home** → `AppleSpotlight` overlay: floating field, animated placeholder, Stage 0–4 shortcut circles, live ranked results. Auto-opens once per session; ⌘K/Ctrl+K and the navbar trigger reopen it.
- **Chapters** → `ExpandableSearchBar` in the navbar: 40px circle expanding into a pill; typing shows a results dropdown in the supplied card style; Enter opens the highlighted chapter.

Both consume the existing build-time index and ranking. No new dependency, no backend, no Algolia.

**Fidelity rule (owner preference):** keep the supplied look as given — blob SVG filter, springs/layout animation, 64px shortcut circles at 30% opacity, result-card shape. Only mechanical changes: Tailwind → CSS Modules on `--tbb-*` tokens, `framer-motion` → installed `motion/react`, `@/lib/utils` → `clsx`, placeholder external links → internal routing, plus the repo's a11y contract (Escape, focus, 44px targets, reduced motion, dark mode).

## Technical Context

- Docusaurus 3 (TypeScript, MDX), Infima, CSS Modules + global stylesheets (`radix.css`, `openprops.css`, `custom.css`, `a11y.css`).
- Installed and reused: `motion` (Framer Motion v11), `lucide-react`, `clsx`, `@docusaurus/router` (`useLocation`, `useHistory`), `@docusaurus/Translate`.
- Search data: `static/search-index.json`, generated by `scripts/generate-search-index.mjs` (build step; also runnable by hand for dev).
- Verified integration facts: `Root` renders inside `BrowserRouter` (`@docusaurus/core/lib/client/App.js`, `clientEntry.js`), so `useLocation` is valid there; `@theme/Navbar/Search` wraps the swizzled `SearchBar` in `div.navbarSearchContainer` (absolute-right below 996px); `a11y.css` zero-specificity `:where()` rules are overridable by module classes, so component focus rings/target sizes live in the modules where necessary.
- Constraints: no Tailwind/shadcn (normative do-not-add); no new deps; free tier; spec → plan → tasks before code; no version control commands.

## Design detail

### AppleSpotlight (home)
- Keep from the supplied reference: `SVGFilter` + `#blob`; overlay `fixed inset-0` with no dim layer; spring entrance/exit (`blur(20px) url(#blob)`, `scaleX 1.3`, `scaleY 1.1`, y ∓10); `SpotlightInput` autofocus; placeholder-swap logic (hovered shortcut → label; hovered result → label; else "Search"); placeholder filter-blur crossfade; shortcut circles 64px, icon 28px, opacity 30%→100% on hover, `shadow-lg`; supplied stagger/spring math (literal `64 * (index + 1)`); results container with staggered rows and the card look (icon slot 32px, medium label, 12px 50%-opacity description, chevron appearing on hover).
- Mechanical: `motion/react`; CSS Modules; tokens (panel `--tbb-surface` / hover row background → white/silver-0 equivalent; text `--tbb-text`; muted `--tbb-text-muted`; hairline borders; `--tbb-shadow-lg`); dark overrides for every surface.
- Live behaviour: `useRankedResults` supplies hits; row label = title, description = matched heading, else clamped excerpt; row icon = stage glyph when `stageNumberFromRoute(route)` matches, else `FileText`.
- Shortcuts: `STAGE_LINKS` × `StageGlyph`, activated by button (not `target="_blank"`), navigating via router.
- A11y additions: `role="dialog" aria-modal`, labelled; Escape; focus restore; listbox/option + Arrow/Enter; scroll lock; `useReducedMotion()` guard on the filter/scale entrance.
- z-index: above the fixed navbar, below the SiteDrawer layers.

### ExpandableSearchBar (chapters)
- Keep: 40px collapsed circle; expansion spring (260/26); right-anchored growth (`expandDirection="left"` in the navbar); inner search icon at the left; animated left-aligned placeholder; submit-arrow button; outside-click collapse only when the field is empty; 120ms focus delay.
- Mechanical: `motion/react`; CSS Modules; tokens (`--tbb-bg` pill, `--tbb-surface` circle, `--tbb-border`, `--tbb-text`); de-duplicate the supplied file's accidental doubled `useEffect` blocks (no visual change).
- Dropdown: absolute under the pill (`top: calc(100% + 0.5rem)`, right-aligned); width `min(24rem, calc(100vw - 1.5rem))`; shared `SearchResultRow`s; "No matches." status with `role="status"`; combobox/listbox semantics + Arrow/Enter on the input; Escape closes and clears.
- Targets: 40px visual pinned in the module; an invisible `::after` extends the hit area to 44px; input keeps a visible `:focus-visible` ring (navbar chrome, matching the retired surface's contract).

### Entry + provider
- `theme/SearchBar/index.tsx`: no window access at render (SSR-safe).
- `SearchUXProvider`: auto-open effect guarded by `sessionStorage` (skipped when storage throws); ⌘K bound only on `/`; overlay rendered only on `/` and only when open; unmount resets internal state.

## Non-goals

No backend/Qdrant/Algolia search, no `/search` page, no dependency additions, no index-script or record-shape changes, no ⌘K on docs routes, no change to the `Navbar/Content` swizzle or `docusaurus.config.ts` navbar items.

## Risks

1. `filter: url(#blob)` + `backdrop-filter` glass can render oddly in some browsers — fallback: drop the SVG filter from the `filter` value (keep blur); look otherwise unchanged.
2. lucide glyphs (Search/X/FileText) vs the site's Phosphor vocabulary — match the supplied stroke widths optically; Phosphor substitution is the sanctioned fallback if the clash is visible.
3. Replacing the old search CSS wholesale can orphan a11y selectors — mitigated by the `navbar__search` grep check (SC-006) and `test:a11y`.
