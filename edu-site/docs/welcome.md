# Welcome

**Welcome to The Bridge Balance — a free book that takes you from no coding background to leading AI agents with engineering judgment, and to building AI agents of your own.**

The content is 100% free, and the book is in Alpha today: real enough to read, and still being written.

This page is the front door. Read it first, because it decides whether the book is for you. In a few minutes it covers:

- **The problem** the book was written for, and the two habits that fail at it.
- **Code Literacy** and **Spec-Driven Engineering**, the two ideas everything else rests on.
- **The three stages**, what each one teaches, and how the learning runs inside them.
- **What you need to start**, which is very little, and what you do not need at all.
- **How the book was built, where it stands today, and what is coming next.**

Nothing on this page assumes you have programmed before. If you have never written a line of code, you are in the right place.

## Why this book exists, and the two habits it replaces

The industry has split into two habits, and **both of them fail**. One refuses AI coding agents outright and falls behind the people who use them. The other hands over the whole job and never checks the result. That second habit has a name now: [*vibe coding*](/glossary#vibe-coding).

Trusting the output without checking it **costs more than it looks like it does**. A 2025 study by METR found that experienced developers took 19% longer to finish real coding tasks when they used AI tools. The same developers believed the tools had made them faster. Feeling fast and being fast turned out to be two different things.

This book sits between the two habits. Use the most advanced AI models and coding agents available, and check their work yourself. **Checking is a skill rather than a habit of mind**, so this book teaches it — and the whole method below is built around it.

## How this book treats AI, and what it specialises in

Most courses teach one thing at a time. Programming first, then Git, then databases, and AI at the very end, if it arrives at all. Real work does not happen in that order, and neither does this book.

| What most courses do | What this book does |
|---|---|
| Teach programming first, and AI last | Learn the engineering and the AI together, in the same chapter, from the start |
| Treat coding agents as one final topic | Put the better use of today's strongest coding agents first, and stay on it |
| Assume the code the AI writes is code you never read | Teach you to read and judge whatever wrote the code, and to own the result |

The book puts the better use of the most advanced AI models and coding agents first, instead of resisting them. The agents it works with include **Claude Code, OpenCode, Codex and Cursor**. It specialises in exactly that, alongside the engineering fundamentals that make an agent's output judgeable in the first place.

## Code Literacy: reading and judging code, and why it decides everything

Writing code is no longer the scarce skill. An agent can produce more code in a minute than you could type in an hour. **What almost nobody has is the ability to look at that code and say whether it is right.**

This book calls that skill [*Code Literacy*](/glossary#code-literacy): reading and judging code, whoever or whatever wrote it. It is not a side benefit of the course. It is the core skill the whole book builds, and it matters most in exactly the situation that is now normal — an AI wrote the code, and a person still has to answer for it.

Code Literacy has two halves, and both are taught. One half is **reading**: following what a piece of code actually does, step by step. The other is **judging**: comparing what it does against what you asked for, and deciding whether the difference matters.

<Callout type="warning" title="Safety floor">
Whatever the AI writes for you, it is not finished until you have checked it yourself. The AI cannot tell whether its answer is right — it can only produce one. And if something breaks later, "the AI wrote it" is not an answer anyone will accept. The work is yours.
</Callout>

## What Spec-Driven Engineering is, in plain words

Spec-Driven Engineering is the method this book runs on. It is four moves, and **you make the last one yourself**.

| The move | What it means in practice |
|---|---|
| **Specify** | Write down what you want built, and what must not change, before any code exists |
| **Build** | Let an AI agent write the code inside those limits — that part it does faster than you |
| **Verify** | Check the result against the spec you wrote, not against how confident the agent sounds |
| **Own** | Decide whether it is right, and take responsibility for it once you say yes |

The order matters more than any single step. A spec written after the code is a description, not a specification. Checking without a spec is guessing with extra confidence.

## The three stages, and how the learning runs in parallel

The book has **three stages**, and they run in order. Inside each stage, the subjects are learned side by side rather than one after another.

| Stage | What you learn side by side | What you leave able to do |
|---|---|---|
| **0 — Introduction to SDE** | The history of computing, read in the order it happened, from switches and binary to today's AI coding agents — with Spec-Driven Engineering and Code Literacy arriving as the ideas the rest of the book depends on | Explain what a computer is actually doing, and why the engineering discipline around AI exists at all |
| **1 — SDE Mastery (AI-Driven)** | Basic to intermediate engineering — programming, architecture, frontend, backend, databases, Git — learned together with coding agents, prompt engineering, context engineering, and the tools around them | Ship a working application built under your own spec, read its code well enough to own it, and direct a coding agent with real judgment |
| **2 — SDE Mastery (AI-Native)** | Advanced engineering, with advanced agentic work: tool calling, retrieval, evaluations, and multi-agent systems | Design and build AI agents of your own, not only use someone else's |

SDE is short for Spec-Driven Engineering, the method in the table above.

The stages run in order. **The subjects inside them do not.** You do not spend a year on programming and then meet AI at the end. Engineering topics and agentic topics are learned together, in the same chapter, because that is how they are used together. Stages 0 and 1 assume you have never programmed, and Stage 2 builds on them.

One thing this page will never carry: a chapter list. The three stages are fixed, and **the chapters inside them are decided when each one is written**, so the book grows instead of filling in a plan it made too early.

## What you need to start, and what you don't

Every reader's professional background is respected here. If you already work, in any field, technical or not, **the experience you bring is an asset**. This book treats it as something you have, never as a gap you should be embarrassed about.

| You need | You don't need |
|---|---|
| A laptop or desktop — Windows, Mac, or Linux, any of them work | A computer science degree, or any degree at all |
| Enough internet access to load a page | A paid subscription — the content is free |
| Curiosity: a willingness to try things, not only read about them | Prior programming experience — Stages 0 and 1 assume none |
| Patience for long-form reading, not a highlight reel | A signup, an account, or a sign-in — none exist on this site |
| Consistency over speed — a little at a time is a real strategy here | Prior AI or machine-learning experience |

## How this book was built, and what it cost

The book did not start from a blank page, and it was not assembled in an afternoon.

- **Months of research and planning went in first, and weeks of development so far.** Every structural decision was researched before it was made, and most of them were rewritten once the research came back.
- **Books, documentaries, talks and the views of industry leaders were studied and compared.** Among them **Andrew Ng**, who co-founded Coursera and founded DeepLearning.AI; **David J. Malan**, whose introductory computer science lectures have been watched by more than a million people; and **Irfan Malik**, founder and CEO of Xeven Solutions. Many others sit behind them, named and unnamed.
- **Hours of discussion with working experts** shaped what a stage teaches and in what order.
- **The aim was to find what all of them missed.** Not to average the existing courses, and not to copy one of them. The gap this book works on is the one they share: nearly all of them teach you to write code at a moment when reading it has become the harder half.
- **A real cost stands behind this, and it was carried so the content stays free.** The free part is the book, and the book is not the thing that gets sold later.

We studied their public work; **none of them is affiliated with The Bridge Balance or has endorsed it**.
